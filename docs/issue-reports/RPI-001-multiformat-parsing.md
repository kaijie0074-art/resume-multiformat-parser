# 问题报告 RPI-001/RPI-002/RPI-003：简历多格式入口解析错乱与静默失败

- 编号：RPI-001（双栏交错）/ RPI-002（图片型静默失败）/ RPI-003（docx 表格粉碎）
- 报告人：杨凯杰（工程师）
- 日期：2026-10-10
- 严重级：P0（解析是全产品第一公里，错一个字段下游全错且用户无感知）
- 状态：已修复（PR #1 合并于 2026-10-13，见 docs/repair-references.md）

## 现象

`POST /api/resume/upload`，用户从小程序上传简历。三类主流输入全部出错：

1. **RPI-001 双栏交错**：超级简历/五百丁类设计模板几乎全是双栏（左侧时间轴+技能，右侧经历）。基线按 PDF 内容流线性抽取——内容流按**视觉行序**交错绘制，输出"电话 / 实习经历 / 邮箱 / 公司A职责 / 日期 / 教育 / 职责1 / 学校…"的碎片汤。公司 A 的职责挂到公司 B 名下。
2. **RPI-002 图片型静默失败**：手机扫描/截图转 PDF 无文本层，抽取返回空串。基线不判空直接喂给下游 LLM"请优化这份简历"——模型基于岗位描述**编造一份完整简历**（与结构化输出仓库的 L5 捏造层耦合，但根源在此）。
3. **RPI-003 docx 表格粉碎**：学校就业中心 Word 模板用表格排版，合并单元格抽取重复、字段散成不可重组的碎片。

关键认知：前端 1% 的偏差经下游 LLM 推理放大成结构性错误（时间线错乱 → LLM 推断"2024 年同时在两家公司全职"），且**中间无任何告警**——误差在管线最前端生成、在最后端被用户发现。

## 复现（确定性语料）

35 份程序合成语料（固定种子 20261013，无真实 PII）：
10 单栏文本 PDF + 10 双栏文本 PDF（按视觉行序交错绘制，复刻设计模板内容流形态）+ 10 图片型 PDF（位图整页）+ 5 docx 表格简历。见 [docs/reproductions/README.md](../reproductions/README.md)。

## 基线量化（v0.1.0，字段级 F1）

| 输入类别 | 基线 F1 | 主要错误 |
|---|---|---|
| 单栏文本 PDF | 1.00 | —（线性抽取在单栏上无问题） |
| 双栏文本 PDF | **0.78** | 职责错挂（work 三元组 desc/company 配对错误） |
| 图片型 PDF | **0.00** | 空文本层，全部字段缺失，静默失败 |
| docx 表格 | 1.00* | *v0.1.0 用 python-docx 简单抽取可对齐；合并单元格重复问题由 v1.0.0 的去重逻辑防御（测试覆盖） |

## 根因

1. 无路由：所有输入走同一条"线性抽取"路径，不区分有无文本层、单栏/双栏
2. 无版面感知：不知道词坐标，双栏内容流交错无法恢复阅读顺序
3. 无失败显式化：空文本不报错、静默通过，把错误推给下游放大

## 验收标准（DoD）

- [x] 路由决策可解释：kind/text_layer/layout + reason
- [x] 双栏 F1 ≥0.95（实测 1.00），职责不串公司有专项断言
- [x] 图片型 F1 ≥0.85（实测 0.92，OCR 回放路径），无 OCR 后端时显式失败（含配置指引）
- [x] docx 表格 F1 ≥0.95（实测 1.00），合并单元格不重复
- [x] 缺失字段 needs_manual + warnings（下游回退让用户手动补）
- [x] CI 跑全量测试与评估
